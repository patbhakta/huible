# [06] Testing Strategy

The testing strategy for the Huible memory-driven persona engine is organized around **numbered gate suites (F1–F8)**, each tied to a specific invariant or exit criterion. Every gate must stay green on `main`; a regression in any gate suite blocks merge.

**Source:** Codified from the existing F1–F8 test suites under `tests/`, the invariant table in `docs/ENGINE_SPEC.md` §7, and the F1 gate report at `docs/f1_gate_report.md`. This document makes the existing testing practice explicit and linkable.

---

## 1. Philosophy

1. **Invariants are tested, not just features.** Each hard rule (INV-1, INV-15, INV-16, INV-FL, INV-DS, INV-CI) has at least one gate suite that fails loudly if the rule is broken.
2. **Exit gates prove phases.** Phase 1 succeeds when F1 passes. Phase 2 will introduce its own voice-test gate. Gates are the contract between phases.
3. **Algorithm-level tests run everywhere; production-scale benchmarks run where the infra exists.** Spreading-activation correctness is tested in-memory with real cosine similarity. 100K-node benchmarks require PostgreSQL + pgvector HNSW indexes.
4. **Append-only versioning applies to tests too.** When an invariant tightens, add a test; do not weaken an existing assertion to make a regression pass.

### 2.1 F1 — Phase 1 Exit Gate

F1 is the contractual exit gate for Phase 1. It is a **retrieval test, not a conversation test**. Phase 1 cannot end until all five F1 criteria pass.

| Criterion | Status | What proves it |
|-----------|--------|----------------|
| F1.1 Indexing | PASS | 1000+ synthetic memories indexed with all three embedding vectors (content 1536d, sensory 1536d, affect 512d) |
| F1.2 Spreading Activation | PASS | Retrieval traverses graph edges, not just nearest neighbors |
| F1.3 Feedback Loop Suppression | PASS | A repeated query returns a different result set (recent nodes suppressed) |
| F1.4 Disclosure Tier Scoping | PASS | `private`-scoped memories excluded when querying as a lower tier |
| F1.5 Cross-Topic Motif Escalation | PASS | Activated set includes motif-boosted cross-topic memories |

**Performance benchmarks (F1 / F8):**

| Benchmark | Budget | Status |
|-----------|--------|--------|
| Spread activation (100K nodes, 500K edges) | < 5s | PASS |
| Suppression (100K activation map) | < 50ms | PASS |
| Motif escalation (100K activation map) | < 500ms | PASS |
| Disclosure filter (100K activation map) | < 500ms | PASS |
| In-memory retrieval (5K corpus) | < 2s | PASS |
| Indexing throughput | > 100/s | PASS |

Latest results are committed at `docs/f1_gate_report.md` (human-readable) and `docs/f1_gate_report.json` (machine-readable), generated by `tests/f1/report.py`.

### 2.2 F2 — Five-Gate Firewall (INV-15)

Unit tests for each gate plus a pipeline integration test. Guards INV-15: **no memory enters the graph without passing all five gates.**

- `test_f2_1_safety_gate.py` — injection / adversarial / safety violations
- `test_f2_2_deduplication_gate.py` — cosine > 0.92 near-duplicate rejection
- `test_f2_3_novelty_gate.py` — must connect to ≥1 existing node
- `test_f2_4_immutability_gate.py` — canonical-tier conflict detection
- `test_f2_5_pertinence_gate.py` — character / relationship / biographical depth
- `test_f2_6_pipeline_integration.py` — end-to-end gate ordering and routing

Each gate must return exactly one of `PASS`, `FAIL`, `AMBIGUOUS`. `FAIL` → rejected; `AMBIGUOUS` → quarantine queue with the priority noted in `docs/04-build-plan.md` Task 1.5.

### 2.3 F3 — Quarantine Queue (INV-16)

Guards the priority routing and adjudication lifecycle: `pending` → `adjudicated` → (`promoted` | `rejected`). A SAFETY-ambiguous candidate must outrank a PERTINENCE-ambiguous candidate.

### 2.4 F4 — Memory Versioning (INV-16)

Guards append-only versioning: memories are **superseded, never overwritten**. Covers `supersedes` / `superseded_by` pointers, `is_active` toggling, and tier promotion (accrued → canonical requires family approval).

### 2.5 F5 — Context Builder

Guards prompt assembly: the system prompt, memory blocks, recent conversation history (last 10 turns), and the knowledge-boundary / era constraints (INV-1) plus disclosure scoping (INV-DS) reach the persona generator in the correct structure.

### 2.6 F6 — End-to-End Ingestion Pipeline

Integration test from conversation → extraction → five-gate firewall → graph persistence. Guards that the async, post-response extraction path does not block persona response latency.

### 2.7 F7 — Disclosure Scoping (INV-DS)

Guards that the requester's relationship tier determines memory access. `private` memories never leak to `close_friends` / `all_contacts` tiers.

### 2.8 F8 — Performance Benchmarks

Codifies the latency/throughput budgets in §2.1 so a performance regression surfaces as a failed test, not a slow deploy.

## 3. Invariant → Test Matrix

Every hard invariant maps to the suite(s) that enforce it. A gap here is a bug.

| Invariant | Rule | Enforced by |
|-----------|------|-------------|
| **INV-1** | Knowledge boundary | F5 (context builder), F1 (era/date filters) |
| **INV-15** | Five-gate ingestion | F2 (gate units + integration), F6 (e2e pipeline) |
| **INV-16** | Append-only versioning | F3 (quarantine lifecycle), F4 (supersede/never-overwrite) |
| **INV-FL** | Feedback loop prevention | F1.3 (suppression) |
| **INV-DS** | Disclosure scoping | F1.4, F5, F7 |
| **INV-CI** | Canonical immutability | F2.4 (immutability gate) + DB trigger |

## 4. Running the Tests

```bash
# Full suite
pytest

# A single gate suite
pytest tests/f1/          # F1: memory retrieval exit gate
pytest tests/f2/          # F2: five-gate firewall
pytest tests/f3/          # F3: quarantine queue
pytest tests/f4/          # F4: memory versioning
pytest tests/f5/          # F5: context builder
pytest tests/f6/          # F6: ingestion pipeline
pytest tests/f7/          # F7: disclosure scoping
pytest tests/f8/          # F8: benchmarks

# Collect-only (count without running)
pytest --collect-only -q

# Regenerate the F1 gate report
python -m tests.f1.report
```

**Test database (when needed):** some tests require PostgreSQL + pgvector. Seed with:

```bash
python -m scripts.seed_data --url postgresql://postgres:postgres@localhost:5432/huible
```

## 5. Conventions

- **Test naming:** `test_f{N}_{description}.py` for gate-suite tests; descriptive names for root tests.
- **Async:** All I/O-touching tests are async; `asyncio_mode = "auto"` is set in the pytest config — no `@pytest.mark.asyncio` boilerplate needed.
- **Fakes:** F1 uses a `CosineFakeBackend` (in-memory) that performs **real** cosine similarity so algorithm-level results are meaningful without a database.
- **Production-scale:** 100K-node benchmarks require PostgreSQL + pgvector HNSW indexes. Algorithm-level correctness is asserted at in-memory scale so the suite runs anywhere.
- **Lint gate:** `ruff check .` (rules: E, F, I, UP, B, SIM, RUF) must be clean before merge.
