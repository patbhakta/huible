## Pipeline (HU-1839 style, relay-free)

- Corpus acquisition: HF `google/frames-benchmark` test.tsv (links only) →
  per-question Wikipedia plaintext via MediaWiki API (`fetch` stage;
  CC BY-SA; 56/79 titles resolved, misses are section-links already
  covered via canonical-title mapping + 8 genuinely dead slugs).
- Landing: verbatim article text = canon → `vault/atoms/`
  (`doc_text` atoms); regenerable chunk index = derived →
  `derived/atoms/`. No blobs in the vault.
- TencentDB tier: 443 chunks (≤8,000 chars, `[[title | qN docM chunkK]]`
  provenance headers) pushed via `/v3/conversation/add` in 16-message
  batches (~1.3 s/message measured; all `code=0`, `stage1_extraction/`).
- Read path: `/recall` per question (query = raw question, prod 2,000-char
  cap) — Arm A strategy on every question; `memory_count` 2-29; excerpts
  carry the doc-header provenance lines, verified against canon
  (20/20 `provenance_ok`).
- Answer + judge: answerer glm-5.3 (z.ai, thinking-off per deployed env
  default) answers strictly from recalled context; judge glm-5.3 fixed.

## Stage attribution from the misses (8/20)

- Retrieval-breadth misses: e.g. q129 needed TWO films; recall surfaced
  only one doc family → partial answer. Breadth is the dominant error
  class in this sample.
- Doc-session shape note: per-question sessions are <40 L0 rows, so the
  40-row gist block never settles — recall rides L0/L1 hybrid + verbatim
  drill-down (the digest component engages only on ≥40-row sessions).
  Recorded honestly per trace (`strategy`, `memory_count`).
- Answerer ran thinking-OFF (deployed `ZAI_THINKING=disabled` env rides
  through `LLMConfig.from_env`) — a thinking-ON ablation is a cheap
  candidate delta.
