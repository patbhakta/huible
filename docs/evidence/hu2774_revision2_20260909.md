## Founder issues -> fixes

1. **"Awkward hard coded Hi, I'm Chandler..."**
   Root cause: two engine behaviors forced intro-style openers in EVERY
   conversation: (a) the M1.6 identity-exchange guard replaced any full-name
   intro with a canned recognition line ("Hey-hey, you know exactly who this
   is.") — wrong when the persona is meeting a stranger; (b) no notion of WHO
   the persona was talking to, so every opener landed the same.
   Fix: `POST /api/v1/chat/{persona_id}` now accepts optional `user_name`
   (schemas.py). The system prompt renders a recognition line (known person:
   "react to {name} the way you actually would — no introductions") or a
   stranger line ("introducing yourself and asking about them is natural").
   The guard's fallback became context-aware: stranger context = first-name
   intro variants ("Chandler. And you are?"); known context = recognition
   variants. Live smoke: stranger "hi, whats your name?" -> "Chandler. Don't
   wear it out. What's yours?"; friend "hey, you free tonight?" (user_name
   Monica) -> "Could I interest you in a couple of beers..." (no intro).

2. **"Super important to know who the persona is talking to"** — covered by
   the same user_name contract. Auto-identity-resolution from working memory
   (engine infers the interlocutor's identity from prior sessions) remains a
   follow-up; the API contract + prompt switching is the interlocutor signal
   for this revision.

3. **"Is it normal for Chandler to only ask one question? For Monica none?"**
   Measured on the 60.8k-line friends-v2 canon corpus: Chandler asks questions
   in **30.9%** of his lines, Monica **33.1%** (Joey 33.5%, Ross 32.6%,
   Rachel 31.3%, Phoebe 28.6%). So no — a 1-question Chandler / 0-question
   Monica run is NOT canon-natural. The evaluator now requires BOTH the
   20–45% band AND >=2 questions per persona. Latest runs: 4–7 questions each.

4. **"Hell bent on sticking to character" / awkward stiffness**: two engine
   defects found live and fixed:
   - Crisis echo-loop: the harness fed the platform's G1 crisis text back into
     the loop; the text contains the very words the deterministic crisis
     classifier keys on -> permanent CRISIS -> canned text forever (observed
     kestra run t14+). Fix: harness never feeds platform text back; a
     platform-text turn is a terminal FAIL (platform-text tell).
   - Distress false positives: bare "lost" ("you just lost by default") and
     "broken" ("phone's broken") flattened the persona voice and, at 2 hits,
     escalated a session to distress_trend_rising -> handoff degraded to the
     G1 canned response + a Sev-1 page. Fix: patterns narrowed to
     person-anchored grief shapes (grief reads preserved; banter no longer
     trips). Memory-recall questions ("what was the first thing I said?")
     are now exempt from the competence wall (they answer from working
     memory, not vault retrieval — the wall had dead-answered the probe).
